# 项目数据层处理说明

系统涉及**三类数据源**,各有独立的处理链路,最终汇入同一个智能体推理上下文:

| 数据源 | 类型 | 更新方式 | 处理模块 |
|---|---|---|---|
| FinDKG-full | 时序知识图谱(静态历史) | 随仓库分发,不更新 | `kg_query.py` → `tools/kg_tools.py` |
| FRED | 宏观经济指标(实时) | 每次调用实时拉取 | `macro_agent.py` → `tools/macro_tools.py` |
| feedback.db | 用户评分反馈(累积) | 每次建议后写入 | `feedback_store.py` → `tools/feedback_tools.py` |

---

## 一、知识图谱数据(FinDKG-full)

### 1. 数据规模与格式

从华尔街日报新闻用 LLM 抽取的**时序知识图谱**:13,645 实体、15 种关系、261 个时间步(周粒度,2018-01-07 ~ 2023-01-01)、242,149 条四元组。

存储为 tab 分隔文本文件:
- `entity2id.txt` — 实体表(名称/ID/索引/类型),实体分 12 类:人物、公司、国家、政府机构、经济概念、指标、商品、行业等
- `relation2id.txt` — 15 种关系
- `time2id.txt` — TimeID(0~260) ↔ 周日期映射
- `train/valid/test.txt` — 四元组本体 `(主语ID, 关系ID, 宾语ID, 时间ID)`

### 2. 加载策略

`FinDKGGraph._load()` 一次性把三个 split(train/valid/test)合并读入 pandas DataFrame,建立双向 ID 映射字典。**不做训练/测试划分**——本项目不训练模型,三个文件合起来当完整事件库用。4MB 数据全内存驻留,查询为毫秒级布尔过滤,无需图数据库。

### 3. 时间窗口检索

`query_entity(entity, n_recent_weeks)`:实体名 → ID → 在时间窗 `[max_time_id - N + 1, max_time_id]` 内筛选"该实体作为主语**或**宾语"的所有三元组 → ID 映射回可读名称 → 按日期倒序。

**关键约束**:"最近 N 周"是相对数据集末尾(2023-01-01)而非当前日期,数据集为静态历史快照。

### 4. 信号极性映射(核心转换)

这是 KG 数据 → LLM 可用信号的关键一步。15 种关系被**人工划定极性**(数据集本身不带极性标注):

- **正面**:`Positive_Impact_On`、`Raise`、`Invests_In`
- **负面**:`Negative_Impact_On`、`Decrease`
- **中性关联**:其余 10 种(`Control`、`Operate_In`、`Impact`、`Announce` 等)

`get_impact_summary()` 按(主语,关系,宾语)三元组分组计数、按频次降序,输出结构化摘要:实体名、时间段、总事件数、三类信号各自的 Top 事件列表。

### 5. 多跳 BFS 关联检索

`get_multihop_context(entity, max_hops=2, max_width=10)`:从目标实体出发做**广度优先遍历**,发现"未直接出现但通过中间节点传导"的关联链。

工程处理:
- **限深**:默认 2 跳(3 跳以上噪声急剧上升)
- **限宽**:每跳最多扩展 10 个新邻居,防止组合爆炸
- **去重**:`visited` 集合避免回路;每个邻居只保留一条代表路径
- **预过滤**:先按时间窗过滤一次三元组表,避免每跳重复过滤

`format_multihop_for_prompt()` 把路径格式化成文本块插入 prompt。

实例(Apple Inc.):第 1 跳发现 `Apple --Control--> App Store`、`Apple --Operate_In--> Tech Sector`;第 2 跳沿 Tech Sector 挖出 `U.S. Federal Reserve --Impact--> Tech Sector`、`China --Impact--> Tech Sector`、以及同板块的 Amazon/Alphabet ——揭示**风险传导路径**,这是单跳查询做不到的。

### 6. 输出裁剪

`tools/kg_tools.query_kg_signals()` 作为工具层出口,每类信号**截断至 Top 6 条**控制上下文预算,附加多跳文本块,以 JSON dict 返回。

## 二、宏观经济数据(FRED)

### 1. 指标选择

从美联储经济数据库(FRED)拉取 5 项指标,覆盖货币政策、利率预期、通胀、就业、市场情绪五个维度:

| 键名 | FRED 序列 | 含义 |
|---|---|---|
| `fed_funds_rate` | FEDFUNDS | 联邦基金利率,货币政策松紧 |
| `treasury_10y` | DGS10 | 10年期国债收益率,长端利率预期 |
| `cpi_yoy` | CPIAUCSL | CPI 同比,通胀水平 |
| `unemployment` | UNRATE | 失业率,劳动力市场 |
| `vix` | VIXCLS | VIX 恐慌指数,风险偏好 |

### 2. 取数与清洗

`_fetch_fred_indicators()` 逐序列调用 `fredapi`:
- **缺失值处理**:`dropna()` 后取最新一期(FRED 序列尾部常有空值)
- **CPI 特殊处理**:原始序列是**指数值**不是同比,取 `iloc[-1]` 与 `iloc[-13]`(12 个月前)计算同比变化率,才是可解读的通胀指标
- **精度统一**:数值统一 `round(2)`
- **容错隔离**:每个指标独立 try/except,单个序列拉取失败记为 `value=None` + 错误信息,**不影响其他指标**——保证部分可用优于全部失败

### 3. 结构化输出

返回 `{指标键: {value, date, label}}`,同时用 `_format_indicators()` 生成人类可读文本块。工具层 `tools/macro_tools.query_macro()` 还附加 `indicator_docs`(每个指标的中文释义),帮助 LLM 正确解读数值含义。

支持**按需取数**:调用方可指定 `indicators=["vix", "cpi_yoy"]` 只拉部分指标,减少 API 调用与上下文占用。

### 4. 时效性说明(已知局限)

FRED 数据为**实时**,而 KG 为**截止 2023-01 的历史数据**,两者存在时间错位。当前系统会把两者作为同一截面呈现给模型,Critic 也未检查此项(其上下文摘要中丢失了日期字段)。这是已识别的待修复问题。

## 三、反馈数据(SQLite)

### 1. 存储结构

`advice_sessions` 表单表设计:实体名、时间窗、KG 时间段、事件总数、**KG 信号快照(JSON)**、建议全文、模型名、评分(+1/0/-1,NULL 表示未评)、备注、时间戳;`entity` 字段建索引。

### 2. 写入时机

单 Agent 和 Multi-Agent 两条链路生成建议后均写入一条记录,返回 `session_id`。Multi-Agent 写入的 KG 快照取自工具调用记录中 `query_kg_signals` 的原始返回(**必须保留每条事件的 `relation` 字段**,否则无法做后续聚合),其中多跳文本因体积大且不参与统计而剔除。

### 3. 聚合统计

`signal_accuracy_report()` 做的是一个**反向关联分析**:遍历所有已评分会话,把每条会话的评分"分摊"给该会话 KG 快照中出现过的每种关系类型,最后按关系类型算平均分。

产出:总评分数、正面评价率、以及每种关系类型的 `{出现次数, 平均评分}`。实测结果如 `Invests_In` 均分 0.786 高于 `Decrease` 0.667,意味着含机构投资信号的建议历史上更受认可。

### 4. 数据回灌

统计结果通过 `get_feedback_stats` 工具**暴露给 Orchestrator**,模型在推理时可主动查询并据此调整信号权重——形成"生成 → 评分 → 统计 → 回灌"的闭环。这是本项目中数据流唯一的反向路径。

## 四、数据验证:信号一致性回测

`backtester.py` 利用 KG 的时间维度做**自验证**,不依赖外部行情数据:

1. 选定历史时间点 T,**仅用 T 之前** 12 周数据统计正负事件数,判定信号方向(positive/negative/mixed/neutral)
2. **仅用 T 之后** 8 周数据统计实际出现的正负事件数
3. 计算一致性得分 ∈ [-1, 1]:方向判断与后续事件同向为正分,反向为负分,mixed/neutral 记 0
4. 滚动回测:从数据集 1/3 处起,每隔 4 周取一个决策点,连续 10 个窗口,汇总平均得分与胜率

**方法论要点**:严格的时间切分保证无 look-ahead bias(判断只用过去、验证只用未来)。**须明确说明**:这验证的是 KG 信号的**自洽性与持续性**,不是投资收益回测——新闻事件信号到股价之间仍隔着市场定价环节。

## 五、跨数据源的统一工程处理

- **路径解析集中化**:所有数据路径候选逻辑统一在 `config.py` 计算一次(项目内优先、外部同级目录兜底),各模块直接消费结果,不重复探测
- **资源单例化**:`tools/resources.py` 提供图谱/存储的懒加载单例,避免同一进程重复加载 24 万行数据
- **统一错误约定**:工具层函数一律返回 dict,失败用 `{"error": ...}` 而非抛异常,保证单个数据源故障不中断整个智能体循环
- **上下文预算控制**:KG 事件每类截断 6 条、多跳限深 2 限宽 10、宏观支持按需取数
- **可测试性**:用合成的最小图谱数据集(3 实体/4 三元组)测查询逻辑,monkeypatch 掉 FRED 网络调用,临时数据库测 SQLite,全部数据层测试零外部依赖
