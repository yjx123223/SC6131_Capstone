# 人工标注指南：跨公司风险事件参考答案

> 用途：为消融实验（见 `eval-design.md`）提供"正确答案"。主指标"跨公司风险召回率"完全依赖这份标注。
> 工作量：约 500 条，每条只看标题和摘要，**1.5–2 小时**，建议分两次做。

---

## 1. 在标注什么

对每家目标公司，系统会拉取它自己和相关公司（供应商、客户、竞争对手、合作伙伴）的近期新闻。
你要回答的是：**这条新闻，是不是一件会对「目标公司」产生实质影响的事？**

标注**单位**是「一条新闻 × 一家目标公司」。同一条台积电的新闻，会分别出现在 AAPL、NVDA、AMD 的候选池里，**要分别判断**——台积电产能紧张对苹果和对英伟达的影响程度可能不同。

⚠️ **标注必须在看系统生成的报告之前完成**，否则参考答案会被系统的输出带偏，实验就失去意义。

---

## 2. 文件长什么样

我会生成 `eval/gold/gold_events.csv`，前 9 列已经填好，**你只需要填最后 3 列**：

| 列 | 谁填 | 说明 |
|---|---|---|
| `id` | 自动 | 行号 |
| `company` | 自动 | **目标公司**（在评估谁的报告） |
| `source_company` | 自动 | 这条新闻是谁的新闻 |
| `hop` | 自动 | 0=目标自己，1=直接关系，2=上游的上游 |
| `relation` | 自动 | 与目标的关系：供应商 / 客户 / 竞争对手 / 合作伙伴 |
| `published_at` `publisher` `title` `summary` `url` | 自动 | 新闻内容 |
| **`material`** | **你填** | 0 或 1 |
| **`impact_on_target`** | **你填** | positive / negative / neutral |
| **`note`** | **你填** | 一句话理由，可选但强烈建议写 |

用 Numbers 或 Excel 打开，填完**另存为 CSV（UTF-8）**即可。

---

## 3. `material` 怎么判断

**同时满足 3 条**才标 1：

**(a) 是一件具体发生的事**，不是行情播报或泛泛评论。
- ✅ 发财报、产品发布、并购、监管调查、诉讼、产能变化、大额订单、高管变动、指引调整
- ❌ "苹果今日涨 2.3%"、"科技股普遍走强"、"五只值得关注的 AI 股"、榜单和推荐类文章

**(b) 有合理的影响通路**。
- `hop=0`：直接关于目标公司 → 通常满足
- `hop≥1`：要能说出一句因果。比如"供应商产能紧张 → 目标公司供货受影响"、"竞争对手发布新品 → 目标公司竞争压力上升"
- 如果只是"同属科技板块，一起涨跌"，**不算**

**(c) 影响是实质性的**，会影响收入、成本、供应、需求、竞争格局或监管风险。
- ❌ 人事花边、纯营销活动、赞助、慈善、办公室搬迁

**其他规则：**
- **重复报道只标一次**：同一件事被多家媒体报道时，选**最早或最具代表性**的那条标 1，其余标 0，并在 note 里写"与 #12 重复"。
- **分析师评级**：目标公司自己被调整评级 → 标 1；**邻居公司**被调整评级 → 标 0（不构成传导）。
- **拿不准就标 0**，并在 note 里写"边界：……"。标注要**偏保守**，宁可漏标也不要把无关新闻算进参考答案——参考答案里混入噪音，会让所有组的召回率一起失真。

---

## 4. `impact_on_target` 怎么填

**始终站在目标公司的角度**，不是新闻主角的角度。这点最容易搞错：

| 新闻 | 目标公司 | 对新闻主角 | **填什么** |
|---|---|---|---|
| 台积电产能紧张 | AAPL（客户） | 负面 | **negative** |
| 微软云业务增速放缓 | AAPL（竞争对手） | 负面 | **positive**（对手承压） |
| 谷歌 Pixel 销量大增 | AAPL（竞争对手） | 正面 | **negative**（竞争压力） |
| 英伟达发布新一代 GPU | MSFT（客户） | 正面 | **positive** |
| 苹果发布 iPhone 18 | AAPL（自己） | 正面 | **positive** |

`material=0` 的行，这一列留空即可。

## 6. 建议的操作节奏

1. **先按 `company` 排序**，一家公司一家公司地看，脑子里保持同一个"目标视角"，比跳着看快很多。
2. 每条只看**标题 + 摘要**，10–20 秒决定，不要点开原文。
3. 一次做 7–8 家公司（约 250 条），休息一下再做剩下的。**疲劳是标注质量的最大敌人。**
4. 遇到反复出现的新类型（比如"财报预告"算不算），先记在 note 里，标完一家公司后统一回头修正，并把规则补进本文档第 3 节。

---

## 7. 质量自检（必做，10 分钟）

标完之后：

1. 随机抽 30 条，**第二天**在看不到第一次结果的情况下重标一遍。
2. 计算自一致率 = 两次结果相同的条数 / 30。
3. **目标 ≥ 0.85**。低于这个值，说明规则还不够清晰，需要先修规则再重标——这一步会直接写进实验报告的局限性部分。

我会提供一个脚本自动算自一致率，并统计标注分布（每家公司有多少条 material=1、hop 分布如何）。如果某家公司一条都没标出来，它在召回率计算中会被排除，需要提前发现。

## 8. 常见问题

**Q：新闻是英文的，看不太懂怎么办？**
只看标题里的关键动词即可：warns / cuts / halts / launches / acquires / sues / probes / upgrades。拿不准就标 0。

**Q：一条新闻同时影响目标公司和邻居公司？**
按"对目标公司"的角度标。候选池里如果这条新闻在不同目标下出现多次，分别判断。

**Q：标注的多少会影响实验结论吗？**
会。标得太松，参考答案里混入噪音，三组的召回率会一起被拉低；标得太严，召回率普遍偏高、区分度下降。**保持一致**比松紧本身更重要。
